# 隐患检查项后台

> 2026-05-27 开始。跨 admin-hub + hazard-detect 两个项目。

## 目标

admin-hub 加一个「隐患检查项」长页面，可看可改 hazard-detect 的 36 个场景 prompts。**保存后影响真实 AI 识图**：用户下次上传图片，hazard-detect 用新的 prompts。

## 当前数据形态

`hazard-detect/lib/prompts.js` 1641 行 ESM 源码，导出 `SCENARIO_LABELS`（36 个）+ `SCENARIO_PROMPTS`（每个含 `name`/`context`/`focus[]`）+ `buildSystemPrompt`/`parseResult` 函数。server.js 启动时静态 import 一次。

## 架构决定

- **数据存储**：抽到 `hazard-detect/data/prompts.json`，hazard-detect 仓库提交一份 seed 进 git
- **加载方式**：hazard-detect 每次 `/api/analyze` 调用时 `fs.readFileSync` 读 JSON（不缓存，admin-hub 改完零延迟生效，免重启）
- **写入归属**：admin-hub 通过 `HAZARD_PROMPTS_PATH` env（绝对路径）写 JSON；写入前 schema 校验 + 原子写 + `.bak.<ts>` 自动备份
- **权限**：仅超管可见可写
- **入口**：侧边栏「系统管理」section 新增「隐患检查项」

## Phase 拆解 & 验收

| Phase | 内容 | 验收 |
|---|---|---|
| 1 | hazard-detect 抽 JSON + loader 改造 | 本机 `npm run dev`，同一张图同一场景，AI 输出与改造前一致 |
| 2 | admin-hub 后端 API（GET/PUT） | curl 拿到完整结构；PUT 后 JSON 真改，`.bak` 文件生成 |
| 3 | admin-hub 前端长页面 | 36 场景全部渲染；某场景改一字 → 保存 → 刷新仍在 |
| 4 | 侧边栏 + 权限 | 超管看见入口，普通管理员看不见 |
| 5 | 部署验证 | 后台改一字 → 调 AI 识图 → 输出确实包含新文案的指引 |

## 已知风险

- **跨项目写文件**：本机 OK（admin-hub 已经用绝对路径读 career-report/career-nav sqlite）；生产同机部署，复用同一模式
- **JSON 写坏 hazard-detect 起不来**：用每次读 + try/catch fallback 到内存里的最近一次成功值，避免单次写错把服务搞挂
- **git pull 覆盖本地改动**：hazard-detect/data/prompts.json 进 git 但部署时用 `git pull --no-rebase` 默认会冲突 —— 改成 `.gitignore` + 提交 `prompts.seed.json`，首次部署 cp 一份
- **1641 行内容前端一次性渲染**：浏览器没问题但 token 大。前端用「场景列表 + 点开编辑当前场景」而非全展开
- **跨项目所有权变更**：hazard-detect README 加一句「prompts 由 admin-hub 维护」

## 决策点（已敲定）

- ✅ 保存后真实影响 AI（用户选项 A）
- ✅ 用 JSON 文件方案（不走 DB / 不走 admin-hub→hazard-detect HTTP）
- ✅ 编辑粒度：场景级保存（每个场景独立保存按钮，避免一次保存全部 36 个的爆炸半径）
- ✅ 权限：仅超管
