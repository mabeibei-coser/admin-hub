# admin-hub 对外接入开发规范

> **本文档读者**：AI 开发助手（Cursor / Claude Code / Copilot 等）。
> **使用场景**：你正在为「永升服务」的某个 C 端业务项目写代码，这个项目最终要接入名为
> `admin-hub` 的跨业务管理后台。本文档是接入方对你输出的项目的**硬性契约**——满足这些条件，
> 项目交付后无需返工就能挂到后台；不满足，接管方要先反过来改造，会被退回返工。
> **不是教程**。是验收清单 + 实现模板。**默认按本文照做**，偏离任何一条都要在 README 写明理由。
> **版本**：v1（2026-05-28）；**配套模板**：本文档同目录 `templates/`；**对应后台**：admin-hub `/b100`。

---

## 0. 一句话总览

> 你开发的业务项目本质是「**用户填表 → AI 生成报告 → 持久化到本地 SQLite → 用户浏览**」。
> admin-hub 通过 `ATTACH DATABASE` 直接挂载你的 SQLite 文件做**只读统计与报告查看**。
> 因此你的项目必须：用 `better-sqlite3` + WAL 模式 + 固定 schema 的 `reports` 表 + 手机号登录 +
> 单 Node 进程后端 + 标准 env 命名 + 文档齐全。

## 0.1 必读上下文（30 秒读完）

| 名词 | 含义 |
|---|---|
| **admin-hub** | 后台项目，Next.js 16 + TS + better-sqlite3，部署在 `https://h100.jsai100.com/b100/` |
| **你的项目** | 一个独立的业务项目（如薪资查询、简历优化），有独立 git 仓、独立部署、独立 SQLite 数据库文件 |
| **接入方式** | admin-hub 在它的 `.env` 里配置 `<你项目>_DB_PATH`，启动时 `ATTACH DATABASE` 把你的 `.db` 文件挂成一个只读 schema；它只读你的 `reports` 表，不写 |
| **跨进程并发** | 你的 Node 进程在写，admin-hub 的 Node 进程在读，**同一个 sqlite 文件**——所以必须开 WAL 模式，否则会有 `SQLITE_BUSY` 死锁 |
| **报告内容** | 完整结构化 JSON 直接存进 `reports.report_json` 文本列，不要拆表 |
| **用户身份** | 用户填表前要登录（默认手机号无 OTP），姓名/手机号埋在 `form_data_json` 或直接做列；admin-hub 用 `json_extract` 取 |

## 1. A 组：硬约束（10 条，违反 = 接不进来）

> 这 10 条是 admin-hub `ATTACH DATABASE` + 报告聚合机制能跑通的物理前提。**任何一条不满足**，
> admin-hub 在后台启动时就会自动降级把你的项目"关闭"。**不要试图绕过任何一条**。

### A1. 数据库驱动必须是 `better-sqlite3`

- ✅ 允许：`"better-sqlite3": "^11.5.0"` 或更高（admin-hub 当前 ^12.10.0，建议你也用 ^12.10.0 保持 ABI 一致）。
- ❌ 禁止：`sqlite3`、`node-sqlite3`、`sql.js`、`bun:sqlite`、`@libsql/client`、`drizzle`+其他后端、`prisma`+其他后端。
- ❌ 禁止：`pg`、`mysql2`、`mongodb`、`mongoose`、`@supabase/*`、`firebase`。admin-hub 是 ATTACH 本地文件，跨进程访问云数据库无解。
- **判定**：`grep -E '"(sqlite3|node-sqlite3|sql\.js|pg|mysql2|mongodb)"' package.json` 必须无输出；`grep '"better-sqlite3"' package.json` 必须有输出。
- **为什么**：ATTACH 机制只能跨 better-sqlite3 进程工作。其他驱动有自己的连接池/序列化，与 admin-hub 不兼容。

### A2. SQLite 必须开启 WAL 模式 + `busy_timeout`

```js
const db = new Database(DB_PATH);
db.pragma("journal_mode = WAL");
db.pragma("busy_timeout = 5000");
```

- **判定**：`grep -r 'journal_mode.*=.*WAL' --include="*.js" --include="*.ts" .` 必须有匹配。
- **为什么**：admin-hub 与你的项目同时打开同一个 `.db` 文件。不开 WAL → 你的写入会被 admin-hub 的读阻塞 → 用户提交报告时 hang / 报错。`busy_timeout` 保证偶发竞争时自动重试 5 秒。

### A3. 数据库文件必须放在项目根 `data/` 目录下，路径走 env

```
<your-project>/
  data/
    <your-project>.db        ← 实际文件
    <your-project>.db-wal    ← WAL 副本（自动生成）
    <your-project>.db-shm    ← 共享内存（自动生成）
```

```js
const DATA_DIR = path.join(PROJECT_ROOT, "data");
const DB_PATH = process.env.<YOUR_PROJECT>_DB_PATH || path.join(DATA_DIR, "<your-project>.db");
```

- `<YOUR_PROJECT>` 是项目名的大写蛇形（kebab → SCREAMING_SNAKE）。如 `salary-report` → `SALARY_DB_PATH`，`hazard-detect` → `HAZARD_DB_PATH`。**全大写 + 下划线**，不允许中文，不允许小写。
- **判定**：项目根有 `data/` 目录；`grep -E 'process\.env\.[A-Z_]+_DB_PATH' lib/db.*` 必须匹配。
- **❌ 禁止**：把 `data/` 放在 OneDrive / 坚果云 / Nutstore / Dropbox / Google Drive 等任何云同步目录里。**云同步 agent 会破坏 SQLite WAL 文件，导致数据库损坏**。如果用户的项目根本身在云盘里，必须改用 `<YOUR_PROJECT>_DB_PATH` 指向本机本地路径（如 `D:/data/your-project.db`）。

### A4. 必须有 `users` 表，最小 schema 如下

```sql
CREATE TABLE IF NOT EXISTS users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  phone         TEXT    NOT NULL UNIQUE,
  created_at    INTEGER NOT NULL,          -- 毫秒时间戳
  last_login_at INTEGER
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_users_phone ON users(phone);
```

- 可以增列（如 `name`、`email`），不能少列。
- `phone` 一定要 UNIQUE，因为登录是 upsert by phone。
- 如果业务不需要登录，**不要跳过 users 表**——加一个 dummy 用户（`id=1, phone='anonymous'`）让 reports 表的外键约束有处可关联。

### A5. 必须有 `reports` 表，固定核心列 + 可选业务列

**核心列（必有，名字不能改）：**

```sql
CREATE TABLE IF NOT EXISTS reports (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id         INTEGER NOT NULL,                       -- 关联 users.id
  user_phone      TEXT    NOT NULL,                       -- denormalize，admin-hub 直查不 JOIN
  created_at      INTEGER NOT NULL,                       -- ⚠️ 毫秒时间戳整数，不是 ISO 字符串
  report_json     TEXT    NOT NULL,                       -- AI 返回的完整结构化 JSON
  duration_ms     INTEGER,                                -- AI 生成耗时（ms），admin-hub KPI 用
  ip              TEXT,                                   -- req.ip
  user_agent      TEXT,                                   -- req.headers['user-agent']
  -- 下面是可选但强烈推荐的列：
  form_data_json  TEXT,                                   -- 用户填表的原始输入（JSON）
  has_resume      INTEGER DEFAULT 0,                      -- 0/1，是否上传了简历
  resume_filename TEXT,                                   -- 简历原始文件名（含扩展名）
  uuid            TEXT,                                   -- 报告对外可访问的随机 ID（可选）
  sections_status TEXT                                    -- 分段生成进度 JSON（可选，多段报告用）
);

CREATE INDEX IF NOT EXISTS idx_reports_created_at ON reports(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_reports_user       ON reports(user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_reports_phone      ON reports(user_phone, created_at DESC);
```

**判定**：

```bash
sqlite3 data/<your-project>.db ".schema reports" | grep -E "id INTEGER|created_at INTEGER|user_phone|report_json"
# 上面 4 个关键字必须都出现
```

**关键 gotcha**：

- ⚠️ `created_at` **必须是 INTEGER 毫秒时间戳**（`Date.now()`），不要用 `TEXT ISO 字符串` 也不要用秒。admin-hub 的所有日期筛选用 `created_at >= ?` 比较整数。
- ⚠️ `report_json` 是 `TEXT` 列（不是 BLOB），存 `JSON.stringify(report)`。完整结构化数据全塞这里，不要拆表。
- ⚠️ `user_phone` 必须 denormalize 一份在 reports 表里（不要让 admin-hub JOIN users 表去拿手机号——跨库 JOIN 性能差，且 admin-hub 不能写）。

### A6. 业务字段：直接列 vs 埋 `form_data_json` 二选一

admin-hub 支持两种数据形态，挑一种保持一致：

**模式 1（推荐——结构简单时）：业务字段直接做列**
```sql
-- 例如 salary-report：
position TEXT NOT NULL, company TEXT NOT NULL, rank TEXT NOT NULL,
education TEXT NOT NULL, city TEXT NOT NULL, rank_label TEXT
```
适合：5-8 个查询条件、字段名稳定。admin-hub 直接 `SELECT col FROM your.reports`。

**模式 2（推荐——结构灵活时）：业务字段塞 `form_data_json`**
```sql
form_data_json TEXT NOT NULL   -- 存 {"name":"张三","phone":"138...","education":"硕士",...}
```
适合：字段会演进（v2 加字段）、字段多（≥10 个）、有嵌套结构。admin-hub 用 `json_extract(form_data_json, '$.name')` 抽。

**两种都允许，但用户姓名/手机号字段名固定**：

| admin-hub 期望读到的逻辑字段 | 模式 1 列名 | 模式 2 JSON key |
|---|---|---|
| 用户姓名 | `user_name` | `form_data_json.name` |
| 用户手机号 | `user_phone`（核心列已有） | `form_data_json.phone` |
| 学历 | `target_education` 或 `education` | `form_data_json.education` |
| 工作年限 | `work_years` | `form_data_json.workYears` |
| 用户身份/标签 | `user_identity` | `form_data_json.identity` |

**判定**：在 `data/<your-project>.db` 上跑下面 SQL，能查出至少 1 条记录的姓名 + 手机号即可：

```sql
SELECT id, user_phone,
       COALESCE(json_extract(form_data_json,'$.name'), user_name, 'MISSING') AS name
FROM reports
ORDER BY id DESC LIMIT 1;
```

### A7. 必须有 `package.json` 顶层 `"name"` 字段，且与项目目录名一致

- `package.json` 的 `name` = 项目目录名（如目录是 `salary-report`，name 必须是 `salary-report` 或 `salary-query-system` 之类**业务相关**的名字，不要叫 `vite-project` / `my-app` / `web` / `test`）。
- **判定**：`node -e "console.log(require('./package.json').name)"` 输出非泛用名。
- **为什么**：admin-hub 的 `.env` 用 `<NAME>_DB_PATH` 命名，要靠这个 name 推断 env 变量名。

### A8. 必须用单一 Node 进程后端（Express 或 Next.js）

允许且仅允许下面 2 种后端形态：

**形态 A：Vite 前端 + Express 后端**（推荐——前端是 React/Vue SPA 时）
- 入口文件：`server.js` 在项目根
- 前端：`vite build` 出 `dist/`
- 生产模式：Express 同时托管 API + `dist/` 静态文件
- 端口：单端口，由 `PORT` env 控制
- 模板：见 `templates/server.js`

**形态 B：Next.js（App Router 或 Pages Router）**
- 入口：`next.config.ts` / `next.config.js`
- API：`app/api/*` 或 `pages/api/*`
- DB 访问：`lib/db.ts` lazy-init 单例
- 端口：单端口，由 `PORT` env 控制
- 模板：参考 admin-hub 自身 `lib/db.ts` + `lib/admin-session.ts`

**❌ 禁止**：
- 多进程架构（前后端两套独立部署）—— admin-hub 部署模型按"单进程"设计
- Python / Go / Rust / PHP 后端 —— driver 不兼容
- Serverless（Vercel Functions / Cloudflare Workers）—— SQLite 文件无处放
- Docker 多容器 —— admin-hub 当前部署不用 docker，路径接不上

### A9. 必须用 `iron-session` 做会话，cookie 名字遵守命名规则

```js
import { getIronSession } from "iron-session";

export const sessionOptions = {
  password: process.env.<YOUR_PROJECT>_SESSION_PASSWORD,    // ≥32 字符
  cookieName: "<your_project>_user_session",                // 全小写 + 下划线
  cookieOptions: {
    secure: process.env.<YOUR_PROJECT>_COOKIE_SECURE !== "false" && process.env.NODE_ENV === "production",
    httpOnly: true,
    sameSite: "lax",
    path: process.env.<YOUR_PROJECT>_COOKIE_PATH || "/",
    maxAge: 60 * 60 * 24 * 30,   // 30 天
  },
};
```

**❌ 禁止**：`express-session`、`next-auth`、`jsonwebtoken`/JWT 自实现、`cookie-session`、其他第三方鉴权 SDK。

**为什么**：admin-hub 也用 iron-session；统一一种 cookie 编码方式，万一以后跨项目共享身份很方便。

**密钥生成**：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

写到 `.env.local` 的 `<YOUR_PROJECT>_SESSION_PASSWORD=`。

### A10. 严禁在 `.env*` 提交到 git

`.gitignore` 必须包含：

```
.env.local
.env*.local
data/
node_modules
dist
```

- `.env.local` 含 API key + session 密钥，泄露 = 钱被烧 + 用户数据被劫
- `data/` 含真实用户数据，绝对不能进 git
- **判定**：`git check-ignore -v .env.local data/` 必须输出 .gitignore 路径，证明被忽略

## 2. B 组：工程规范（7 条，强烈推荐）

### B1. 环境变量命名（**严格遵守**）

| 用途 | env 变量名 | 例子（项目名 = salary-report） |
|---|---|---|
| DB 文件路径 | `<PROJECT>_DB_PATH` | `SALARY_DB_PATH=/var/data/salary.db` |
| iron-session 密钥 | `<PROJECT>_SESSION_PASSWORD` | `SALARY_SESSION_PASSWORD=...` |
| Cookie secure 开关 | `<PROJECT>_COOKIE_SECURE` | `SALARY_COOKIE_SECURE=false` |
| Cookie path（子路径部署时） | `<PROJECT>_COOKIE_PATH` | `SALARY_COOKIE_PATH=/a500` |
| API 服务端口 | `PORT` | `PORT=4001` |
| AI API key | `<VENDOR>_API_KEY` | `IFLYTEK_API_KEY=...` `OPENAI_API_KEY=...` |
| AI 模型名 | `<VENDOR>_MODEL` | `IFLYTEK_MODEL=astron-code-latest` |
| Vite 子路径 | `VITE_BASE_PATH` | `VITE_BASE_PATH=/a500/` |
| Next.js 子路径 | `NEXT_PUBLIC_BASE_PATH` | `NEXT_PUBLIC_BASE_PATH=/a500` |

**`<PROJECT>` 的取值规则**：项目目录名最有辨识度的英文短词，大写蛇形。
- `salary-report` → `SALARY`（不是 `SALARY_REPORT`，太长）
- `hazard-detect` → `HAZARD`
- `ai-interview` → `INTERVIEW`
- `resume-tailor` → `TAILOR`
- 如果短词与已有项目冲突，加修饰：`career-nav` → `NAV`，`career-report` → `REPORT`

### B2. 端口规范

- 默认 `PORT=4001`（Express 服务端口）
- Vite dev 永远跑在 `3000`（前端 dev server）
- 生产环境部署时由 nginx 反代到内网端口（admin-hub 的 deploy skill 会自动分配）
- **不要在代码里硬编码任何端口**，全部走 `process.env.PORT || 4001`

### B3. 子路径部署就绪（basePath）

生产环境会部署到 `https://h100.jsai100.com/a500/`（子路径），开发不需要子路径。代码必须支持：

**Vite 形态（`vite.config.js`）**：
```js
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '');
  return {
    base: env.VITE_BASE_PATH || '/',
    // ...
  };
});
```

**Next.js 形态（`next.config.ts`）**：
```ts
const BASE_PATH = process.env.NEXT_PUBLIC_BASE_PATH ?? "";
const nextConfig: NextConfig = {
  basePath: BASE_PATH,
  trailingSlash: true,
};
```

**客户端 fetch 必须带 basePath**——这是踩坑最深的一条：

```js
// ❌ 错误：固定写 /api，部署到子路径就 404
fetch("/api/login", { ... })

// ✅ 正确（Vite）：通过 import.meta.env.BASE_URL 自动加前缀
const API_BASE = import.meta.env.BASE_URL.replace(/\/$/, "") + "/api";
fetch(`${API_BASE}/login`, { ... })

// ✅ 正确（Next.js）：用 withBase helper
import { withBase } from "@/lib/url";
fetch(withBase("/api/login"), { ... })
```

同理 `window.location.href = ...` / `window.open(...)` / `<a href="/...">` 也都要套 base。`<Link>` 和 `router.push` 自动加 basePath，**不要**手动再加（会双重前缀）。

### B4. 单一进程同时托管 API 和静态资源（Vite 形态）

`server.js` 在生产模式下必须能静态托管 `dist/`：

```js
if (process.env.NODE_ENV === "production") {
  const distDir = path.join(__dirname, "dist");
  app.use(express.static(distDir));
  app.get("*", (req, res) => res.sendFile(path.join(distDir, "index.html")));
}
```

部署时 `npm run build && NODE_ENV=production node server.js` 一条命令搞定，不需要 nginx 单独托管静态资源。

### B5. AI API key 必须留在服务端

**❌ 禁止**：
- 把 AI API key 通过 `VITE_*` env 暴露到前端
- 浏览器直接调讯飞 / OpenAI / Claude / DeepSeek 等任何 AI 服务

**✅ 正确**：
- API key 只在 `server.js` 进程里读取（`process.env.IFLYTEK_API_KEY`），不带 `VITE_` 前缀
- 浏览器 POST 到你自己的 `/api/queries`，由 server.js 内部转发到 AI 提供商

**为什么**：暴露的 key 24 小时内会被脚本 kid 扫到把你的 quota 烧光，账单可达数千元。

### B6. 必须有缓存/幂等机制（推荐，不强制）

用户重复提交同样的查询条件 30 天内应该复用历史结果。模板代码（`templates/server.js`）已实现：

```js
const cached = findCachedReport({ position, company, rank, education, city }, QUERY_CACHE_MS);
if (cached) { /* 直接返回历史 report_json */ }
```

**为什么**：(1) 省 AI quota；(2) 同一用户多次查同条件得到不一样的结果会让用户怀疑数据真实性。

## 3. C 组：文档（6 条，让维护性达标）

### C1. `README.md` 必须存在，必须包含 5 个段落

模板见 `templates/README-template.md`。最小骨架：

```markdown
# <项目名>（业务一句话描述）

<2-3 行业务描述：解决什么问题，给谁用>

## 技术栈
<列出关键库版本>

## 本地跑
<git clone 后两步内能跑起来>

## 用户流程
<3-5 步描述用户从打开页面到看到报告的链路>

## 主要文件
<表格列出 5-10 个关键文件 + 作用>
```

### C2. `README.md` 必须写明 `reports` 表 schema

至少粘贴 `CREATE TABLE reports` 完整 SQL。admin-hub 接管方不需要去翻 db.js 找 schema。

### C3. `README.md` 必须写明 env 列表

每个 env 变量必须列出：(a) 是干嘛的 (b) 必填还是可选 (c) 怎么生成（如果有特殊步骤，比如 session 密钥）。

### C4. `.env.local.example` 必须存在，行数 ≥ env 数量

每个真实 `.env.local` 里用到的变量，`.env.local.example` 都要有对应行 + 注释说明。值用占位符（`<api-key>`、`<generate-with-...>`），不要写真值。

### C5. `.gitignore` 必须正确

## 4. D 组：部署兼容（3 条）

### D1. `package-lock.json` 必须严格匹配 `package.json`

`npm ci --dry-run` 必须返回 0。如果发现 lock 漂移：

```bash
rm package-lock.json
npm install --no-audit --no-fund
npm ci --dry-run    # 必须通过
git add package-lock.json
git commit -m "chore: regenerate package-lock.json"
```

**为什么**：admin-hub 的部署流程在服务器上跑 `npm ci`（不是 `npm install`），lock 漂移会让部署直接失败。

### D2. better-sqlite3 native binding 必须能在 Linux 上构建

- 不要在 `package.json` 锁定 native binding 平台（不要写 `"better-sqlite3": "github:..."` 或 `"optionalDependencies": { ... win32 ... }`）
- `npm install` 必须能自动从 npmjs 拉 prebuilt binary
- 如果本机装失败（中国网络），可以用淘宝镜像：`npm install --registry=https://registry.npmmirror.com`
- 但 `package.json` / `package-lock.json` 里**不要**写死镜像

### D3. 所有路径用相对路径或 env，不写硬编码绝对路径

```js
// ❌ 错
const DB_PATH = "C:/Users/admin/data/salary.db";
const DB_PATH = "/Users/myhusband/projects/salary/data/salary.db";

// ✅ 对
const DATA_DIR = path.join(PROJECT_ROOT, "data");
const DB_PATH = process.env.SALARY_DB_PATH || path.join(DATA_DIR, "salary-report.db");
```

服务器路径会跟本机不一样。开发机和生产机都跑得起来才算交付完成。

## 8. 常见错误模式（容易写错的 8 个反例）

### 8.1 `created_at` 用了字符串/秒

```js
// ❌ 错
created_at TEXT NOT NULL,
db.prepare("INSERT INTO reports (..., created_at, ...) VALUES (..., ?, ...)").run(..., new Date().toISOString(), ...);

// ❌ 也错（秒不是毫秒）
db.prepare("...").run(..., Math.floor(Date.now() / 1000), ...);

// ✅ 对
created_at INTEGER NOT NULL,
db.prepare("...").run(..., Date.now(), ...);   // 13 位整数毫秒
```

### 8.2 没 denormalize `user_phone` 到 reports 表

```js
// ❌ 错：admin-hub 需要 JOIN users 才能拿手机号 → 跨库 JOIN 慢且 admin-hub 不能写
CREATE TABLE reports (id, user_id, ..., report_json);

// ✅ 对
CREATE TABLE reports (id, user_id, user_phone, ..., report_json);
db.prepare("INSERT INTO reports (..., user_phone, ...) VALUES (..., ?, ...)").run(..., phone, ...);
```

### 8.3 把 API key 通过 VITE_ env 暴露到前端

```bash
# ❌ 错：VITE_ 开头的 env 会被打进浏览器 bundle，public 可见
VITE_IFLYTEK_API_KEY=xxx
VITE_OPENAI_API_KEY=xxx

# ✅ 对：无 VITE_ 前缀，只有 server.js 能读到
IFLYTEK_API_KEY=xxx
OPENAI_API_KEY=xxx
```

### 8.4 `iron-session` 密钥里有 `$` 但用了双引号

```bash
# ❌ 错：dotenv 看到 $VAR 会尝试展开，导致密钥被截断
SALARY_SESSION_PASSWORD="abc$1def$2ghi"

# ✅ 对：用 base64 编码的字符串（默认就是无 $）
SALARY_SESSION_PASSWORD=YWJjZGVmZ2hpamtsbW5vcHFyc3R1dnd4eXowMTIzNDU2Nzg5
# 生成命令：
# node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

### 8.5 前端写死 `/api/login`，部署到 `/a500/` 时 404

```js
// ❌ 错：部署到 https://h100.jsai100.com/a500/ 后，请求会发到 /api/login 而不是 /a500/api/login
fetch("/api/login", { ... })

// ✅ 对（Vite）
const API = import.meta.env.BASE_URL.replace(/\/$/, "") + "/api";
fetch(`${API}/login`, { ... })
```

### 8.6 `package.json` name 是 `vite-project`

```json
// ❌ 错
{ "name": "vite-project" }

// ✅ 对（与目录名匹配 + 业务相关）
{ "name": "salary-report" }
```

### 8.7 cookie path 没匹配 basePath

```js
// ❌ 错：basePath=/a500，但 cookie path=/，浏览器在 / 下能看到 cookie，
// 子路径反代时 cookie 不被附加到 /a500/api/* 请求
cookieOptions: { path: "/" }

// ✅ 对：cookie path 与 basePath 严格相等
cookieOptions: { path: process.env.SALARY_COOKIE_PATH || "/" }
// .env.local 写 SALARY_COOKIE_PATH=/a500
```

### 8.8 服务器路径硬编码到代码

```js
// ❌ 错：换台机器 / 部署到 Linux 立刻报错
const DB_PATH = "C:\\Users\\admin\\projects\\salary\\data\\salary.db";

// ✅ 对
const DB_PATH = process.env.SALARY_DB_PATH || path.join(__dirname, "..", "data", "salary-report.db");
```

## 附录 A：字段对照速查表

下面是 admin-hub 列表页 / 详情页期望从你的库读出来的逻辑字段。**至少要支持「核心」组，业务组可选**。

### 核心组（admin-hub 列表页必读）

| admin-hub 期望字段 | 数据类型 | 你这边怎么写 |
|---|---|---|
| `id` | INTEGER | reports.id（主键，自增） |
| `created_at` | INTEGER 毫秒 | reports.created_at = Date.now() |
| `user_phone` | TEXT | reports.user_phone 直接列 |
| `user_name` | TEXT | reports.user_name 列 或 `json_extract(form_data_json,'$.name')` |
| `duration_ms` | INTEGER | reports.duration_ms = AI 调用耗时 |
| `ip` | TEXT | reports.ip = req.ip |

### 业务组（admin-hub 按 project 切分流，能给多少给多少）

| admin-hub 字段 | 含义 | 来源建议 |
|---|---|---|
| `target_position` | 目标岗位/项目名/查询主题 | 直接列 或 form_data_json.position |
| `target_education` | 学历 | form_data_json.education |
| `work_years` | 工作年限 | form_data_json.workYears |
| `user_identity` | 用户身份（学生/在职/创业者等） | form_data_json.identity |
| `target_company` | 目标公司类型 | form_data_json.company |
| `target_city_tier` | 城市层级 | form_data_json.city 或 form_data_json.cityTier |
| `has_resume` | 是否传简历（0/1） | reports.has_resume |
| `resume_filename` | 简历原始文件名 | reports.resume_filename |
| `uuid` | 报告对外随机 ID | reports.uuid（可选） |

### 数据完整性

下面这些情况会让 admin-hub 自动**关闭你的项目入口**（用户在后台看不到你的数据）：

1. `data/<your-project>.db` 文件不存在
2. `data/<your-project>.db` 里没有 `reports` 表
3. `reports` 表缺核心列（id / created_at / user_phone / report_json 中任一）
4. `created_at` 不是 INTEGER 类型

admin-hub 启动时会自动检测，无须你做任何操作；但**不会**告诉你"为什么我项目没出现"，所以你必须在交付前自己跑完 5.1-5.3 自检。
